# 添加地图

复制 `tracks/01_shanghai.json` 为新 JSON 文件，修改稳定 `id`、名称、简介、来源、主题色和控制点。文件名排序决定菜单顺序；建议加数字前缀。重开游戏即可自动发现。

## 字段

- `id`：唯一合法标识符，例如 `ningbo`。也是最佳成绩的独立保存键，不要在发布后随意改名。
- `name` / `subtitle`：菜单和 HUD 显示内容。
- `source` / `reference_km`：布局参考链接和真实赛道资料长度；不用于冒充游戏测量值。
- `color`：六位 HTML 十六进制主题色。
- `points`：按驾驶顺序排列的二维控制点 `[x, y]`。系统用闭合曲线插值，末尾不要重复第一点；第一段是起跑方向，会旋转至游戏前方。
- `scale`：控制点单位到游戏米的缩放。
- `elevation`：平缓周期起伏的幅度（米）。高架基础高度为 32 米，并非真实海拔复刻。
- `gap_anchor`：控制点坐标系下、位于长直道上的断桥中心点。系统选择最近中心线位置，留出约 25 米碰撞缺口。
- `barrier_distance`：沿起点前进多少米放置实体路障。

## 约束与检查

控制点 12–512 个；缩放 0.05–10；相邻点不得重合，缩放后相邻距离 0.25–2500 米；控制折线周长 1000–10000 米；坐标绝对值不超过 100000；起伏幅度不超过 20 米。超范围、无效色值或重复 ID 不加载，避免生成退化道路或无限采样。

道路宽 18 米（含路肩约 20 米）。请保证相近路段足够分开，不要自相交，弯道半径适合真实刚体车辆。曲线会自动平滑，控制点过近、急转或相互穿插依然需要设计者人工检查。

路障建议放在起跑后 80–120 米的直道；断桥应处于至少约 200 米的长直道。确保八个等距检查点及其前进 7 米的恢复位置不落在障碍/缺口上；先运行射线与驾驶测试再交付地图。首批三图已检查。

运行 `tests/run.ps1` 验证现有回归；新增地图后也要把新地图加入集成驾驶验证。菜单会自动发现新文件，测试中的首批数量断言需要随正式地图批次更新。

若以后导出 PCK/EXE，请在 Godot 导出设置的非资源包含过滤器中加入 `tracks/*.json`，并确认导出的包仍能加载地图。
